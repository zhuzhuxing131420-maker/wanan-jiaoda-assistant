## Git 与 GitHub 安全版本管理（用户约定）

- 先只读检查项目 Git 状态、当前分支、HEAD、暂存区、工作区、远程与已有 AGENTS。未由用户选择纳管的项目，不因本全局规则自动初始化、提交或同步。
- 重大修改前：保护未提交工作；有 HEAD 时可建立唯一的本地检查点引用。Git 提交保存审核的版本，临时工作区保护保存未提交修改，完整备份还需包含忽略文件和 Git 元数据；三者不能混称。备份成功须有清单和校验，仓库外唯一新目录存放，明确遗漏。
- 任务完成且通过必要验证后，自动保存当前任务的正式版本，使用简洁中文提交说明。只暂存已审核的明确路径或片段；不得使用无差别全量暂存，不得夹带既有暂存内容、未确认的用户修改或秘密。同文件归属无法分离时先询问。无需为每个微小改动创建提交。
- 保持主分支稳定。复杂功能、重构或构建依赖变更视风险创建独立分支；低风险小修改可沿用当前分支。切换与合并前检查用户工作、验证结果、分支关系和冲突。不擅自改变已有分支策略。
- 默认 GitHub Private，日常本地版本、里程碑同步。先核实账户、远程、分支、仓库可见性、忽略规则、候选文件与将推送历史中的敏感内容。私有不等于可存秘密；只推审核的明确分支，查询远端提交 ID 和隐私状态后才报告同步完成。
- 遇到错误先诊断，优先非破坏性修复和局部恢复。恢复前保护未提交工作；展示相关历史、影响文件和最低风险方案。
- 删除或覆盖文件、丢弃修改、历史重写、强推、删除分支或仓库、公开仓库、覆盖 AGENTS、可能损失数据的恢复和其他高风险不可逆操作，都先解释影响并得到用户确认。禁止未经确认执行 reset --hard、clean -fd 及更强变体或其他等价破坏操作。
- 复用现有 Git、凭据管理与身份；缺失身份需用户确认或从授权账户取得后确认，不伪造，不擅自改写已有配置。登录由用户在官方界面完成，不要求提供令牌或密码；迁移包不含凭据。
- 保留已有 AGENTS 内容，仅在备份后追加独立规则段；追加安装必须幂等。项目级规则优先补充测试、提交与分支限制；明显冲突或安全风险先询问。全局规则不能越过本会话授权或上级指令。
- 日常中文摘要只说明修改、是否提交（提交 ID）、是否同步、风险或待办。失败和未验证的内容明确标注，不夸大保护或同步范围。
- Codex 在新运行中加载适用规则，需核实 CODEX_HOME、override、作用目录和大小限制。AGENTS 是行为指令，不是强制安全隔离，也不会在 Codex 未运行时执行后台任务。
