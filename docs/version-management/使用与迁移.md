# 本项目的版本管理与换电脑指南

## 当前保护和管理方式

Git 保存电脑上审核后的源码版本；GitHub 保存已推送的 Git 版本。手机运行的是 APK，既有 APK 不能替代源码，也不包含应用私有数据。

本项目根目录统一管理 Android 源码、测试、资源、开发脚本和可分享文档。APK、构建目录、local.properties、密钥、缓存、备份、含设备标识的原始记录不上传；原件保留本机。首次配置前完整备份和手机 APK 备份位于本机 Codex 主目录的 backups/wananjiaoda 下，详细清单保留在该位置，不随迁移包分享。

全局 AGENTS 规定通用安全边界，项目 AGENTS 规定本项目测试与限制。规则在 Codex 新运行时加载；同目录 AGENTS.override.md 优先，较深目录细化上层规则。默认项目规则合计大小上限为 32 KiB。需要查看实际加载来源，不能只凭文件存在判断成功。规则不会自动建立后台服务，也不是不可绕过的权限隔离。

## 平时如何使用

在本项目打开 Codex，直接说明任务即可，例如：

> 修改前先保护我的工作。完成这次功能并通过相关验证后，只提交本次任务的内容，使用中文说明；到达稳定里程碑再检查并同步私有 GitHub 仓库。

Codex 应报告修改、提交 ID、同步状态和待处理问题。只有本地提交 ID 不代表已上传；需要远端同分支提交 ID 一致和 Private 状态验证。

手动查看时，在仓库根目录运行：

```powershell
git status --short --branch
git log -5 --oneline --decorate
git diff --stat
git diff --cached --stat
```

`git diff` 查看未暂存修改，`git diff --cached` 查看将要提交的内容。不要把已有暂存内容误当成 Codex 本次工作。

## 检查与保护工具

要求 Windows、Git、PowerShell 7（pwsh）。工具脚本位于 scripts/version-management；在运行前可阅读源码。默认不恢复、不提交、不推送、不删除。

```powershell
pwsh -NoProfile -File scripts/version-management/Inspect-Project.ps1 -ProjectPath .
pwsh -NoProfile -File scripts/version-management/Protect-Worktree.ps1 -ProjectPath . -BackupRoot C:/ProjectBackups -Mode Worktree
pwsh -NoProfile -File scripts/version-management/Protect-Worktree.ps1 -ProjectPath . -BackupRoot C:/ProjectBackups -Mode Full
pwsh -NoProfile -File scripts/version-management/Test-GitSafety.ps1
```

- Git 检查点引用只指向已有提交，不包含未提交修改，也不要求额外提交用户工作。
- Worktree 保护当前 HEAD、状态、索引与工作区补丁及未跟踪非忽略文件；不包含被忽略文件。按工具实际清单核对范围。
- Full 备份包含工作文件、被忽略文件和 Git 元数据；遇到链接、嵌套仓库或无法完整读取的状态会拒绝，不能把失败目录当成功备份。
- 手机 APK 是独立安装包备份，不包含登录、设置和打卡历史等应用私有数据；恢复手机应用需另行评估兼容性和数据影响。

备份目录必须在仓库外，使用唯一目录并核对清单与校验值。备份可能包含密码和私人配置，请放在仅本人可访问的位置；工具不会自动加密，不上传 GitHub。备份失败不得继续重大修改。测试会留下独立临时仓库以便检查，不自动递归删除。

Full 保护普通文件内容，不保留 Windows ACL、备用数据流（ADS）、链接身份，也不是 VSS 或原子快照。运行前关闭其他编辑器和后台写入程序；前后哈希检查仍不能排除文件在过程中变化后又恢复原状的竞态。Worktree 需要匹配的基础仓库和对象，只有 HEAD 字符串不足以独立恢复。工具对自定义 clean/process 过滤器仅在单次 Git 调用中进行安全抑制，不修改用户配置；复制的原始文件是恢复内容依据，补丁供审核参考。工具所生成 Full/Worktree 保护的恢复流程尚未演练，不能将备份校验通过称为恢复验证通过。另行执行的 Git bundle 独立恢复仅验证已提交版本，结果见《配置验证记录》。

当前工具支持普通独立仓库，不支持 linked worktree、子模块、嵌套仓库、稀疏检出、部分克隆、外部 Git 对象库、链接及合并冲突等特殊状态；遇到这些情况会拒绝或报告具名状态。需要由 Codex 另行评估保护方法，不能绕过错误继续。脚本对其他项目的检查不代表用户已选择纳管该项目。

## 提交、分支与同步的实际含义

| 操作 | 实际效果 |
|---|---|
| commit | 把已暂存、已审核的文件保存为本机版本 |
| branch | 从某个版本开出独立修改路线，适合较复杂任务 |
| merge | 把一条路线的提交合并进另一条，需先验证并检查冲突 |
| push | 把审核后的本地提交发送到 GitHub 指定分支 |
| pull | 获取并整合远端修改；整合前必须先保护本机工作、检查分叉 |

Git 姓名和邮箱是提交署名，不等于 GitHub 登录。可以使用 GitHub 提供的 noreply 地址保护邮箱；不要凭空拼接或猜测私人邮箱。

新项目的首次源码基线需要用户确认范围；已有用户工作不能为建立检查点而擅自提交。提交只显式指定本次审核的文件，不使用全量暂存。复杂修改使用任务分支，稳定验证后合并；本地 checkpoint 引用不上传。

## GitHub 私有同步

安装 gh 后先执行 `gh auth status` 查看登录情况。没有登录时，在本人终端运行 `gh auth login --hostname github.com --git-protocol https --web`，在官方浏览器完成授权；不要把令牌发给 Codex，不运行或分享 `gh auth token`。

默认只创建或复用 Private 仓库。首次上传前检查：账户和所有者、远程地址、可见性、分支、远端现有提交、文件与将推送历史中的敏感信息。忽略规则不会从既有历史中移除秘密；若秘密已入历史，停止推送，先说明处理方案，必要时撤销泄露凭据。

日常先查看：

```powershell
gh auth status
git remote -v
git status --short --branch
gh repo view --json nameWithOwner,url,isPrivate,defaultBranchRef
git rev-parse HEAD
git ls-remote origin refs/heads/main
```

本地与远端 main 的完整提交 ID 相同才能说“main 已同步”。里程碑经审核后由 Codex 指定分支推送；不要使用强推、--mirror 或 --all。远端有新提交时先 fetch，再诊断关系；遇到冲突或不相关历史不自动覆盖或硬合并。

## 出错时怎样恢复

先告诉 Codex“检查出错原因，先保护未提交工作，再列出影响最小的恢复方案”。通常先修正具体文件；已经提交的错误可以考虑新增一个撤销提交，以保留历史。`git revert` 也会改变工作文件，需先解释影响并确认，可能产生冲突。

查看历史与某个版本里的文件不会覆盖当前内容：

```powershell
git log --oneline --decorate -10
git show --stat <提交ID>
git show <提交ID>:<仓库内文件路径>
```

不要自行运行 reset --hard、clean -fd、覆盖 checkout/restore、应用补丁或 stash pop 来试运气。得到说明和确认后，才执行可能覆盖、删除或丢失数据的恢复。

## 换 Windows 电脑

1. 先检查 `git --version`、`gh --version`、`pwsh --version` 和已有 Git 身份、凭据管理、AGENTS；有就复用，不覆盖。
2. 从官方来源安装缺失组件，Windows Git 优先保留 Git Credential Manager。无需复制旧电脑的 Credential Manager、密码、令牌或 SSH 私钥。
3. 通过官方浏览器在新电脑独立登录 GitHub，执行 `gh auth status` 验证账户和权限。
4. 从本人 Private 仓库页面复制地址。在新的空路径运行 `gh repo clone <所有者>/<仓库名> <新目录>`，不要克隆到已有项目上。
5. 先读取项目 AGENTS；全局模板位于 docs/version-management/全局规则模板.md，采用备份后追加，若已存在 BEGIN CODEX_SAFE_GIT_V1 标记则不重复追加。模板没有凭据。
6. 确认姓名及 noreply 邮箱，再配置缺失的身份；项目级身份优先，不改写其他项目。
7. 源码恢复后运行检查工具。Android 需要 JDK 21、SDK Platform 36、Build Tools 36.0.0；项目目标 Java 17、Gradle Wrapper 8.13。本机 dev-env.ps1 和 build-debug.ps1 存在固定 D:/AndroidDev 路径，不能假设在新电脑直接可用。
8. 在新电脑源码目录自行生成 local.properties，设置本机 SDK；准备指向该源码的英文目录 Junction 或使用英文检出路径。已有 Junction 需核对，不覆盖。原始私人配置从本人完整备份中按需恢复，先说明覆盖影响。
9. 在配置好的环境中运行 `gradlew.bat testDebugUnitTest --console=plain`；需要 APK 时构建，不自动安装或触发打卡。构建或单元测试通过不能证明手机业务流程通过。

必要的检查命令：

```powershell
git config --show-origin --get-regexp '^(user\.(name|email)|credential\.helper)$'
gh auth status
git status --short --branch
git remote -v
```

如果 GitHub 不可用，可从自己的 Full 备份恢复到新的空目录后检查清单与 Git 状态；不要直接解压覆盖现有工作。`git bundle` 仅包含 Git 对象与引用，不能代替工作文件、忽略文件或完整备份。
