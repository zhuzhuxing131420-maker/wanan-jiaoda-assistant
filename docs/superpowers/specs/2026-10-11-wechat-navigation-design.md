# 微信自动导航设计

用户已选择定时全自动签到，并要求继续开发。本阶段完成从应用按钮启动微信到签到页的导航，复用已验证的单次点击流程；不改默认签到日，不连接定时接收器，不绕过锁屏。

原栈 Kotlin / Compose / 无障碍服务 / 本地中文 OCR / Room 保持不变。真机微信列表节点不可读；比较节点点击、固定坐标和 OCR 后，采用 OCR 连续两帧定位。固定坐标仅用于之前人工调试，不进入产品。

路线：启动微信 → 根据底部标签进入发现 → 小程序 → 最近使用 → 完整名称“晚安交大地学人” → 欢迎确定（如出现） → 进入打卡 → 现有单次签到及当天记录确认。已位于最近使用可直接选择；启动时处于任意小程序则最多返回三次，重新从完整名称选择。省略号名称不作为目标身份依据。未知页面、重复无变化或失去微信前台时超时停止。

纯导航状态机检查帧新鲜度 <=10 秒、两帧间隔 >=500 毫秒、屏幕尺寸一致、候选中心偏移 <=40 像素、合法坐标。手势请求前标记在途；同一步完成后等待页面变化，最多八次导航动作。90 秒导航超时，现有签到阶段另外90秒。页面离开、观察取消和无障碍断开都结束任务。

导航收据只记录步骤和时间，不保存截图及聊天正文。完整名称选择后的新小程序画面才可进入业务流程，业务收据区别人工确认与完整名称导航确认。今天已打卡时只写跳过记录。

验证覆盖名称截断、错误窗口、旧帧、位置变化、重复手势、取消手势、未知小程序、欢迎提示条件和交接条件。安装后从助手按钮启动，真机验证导航到今天已打卡并跳过。项目没有 Git 元数据，实施前源码备份到 D:/AndroidDev/backups/WanAnJiaoDa-before-navigation-20261011.zip。
